## 2. 五条准入规则（每条都有理由）

| 规则 | 拒绝/降级原因 | 文献依据 |
|---|---|---|
| `sensitivity: sensitive` **直接拒写** | 笔记是 git 跟踪的文件；写下去之后"以后再删"是做不到的承诺——git 历史与派生索引都会留痕 | `arXiv:2610.17659`：遗忘的信息可能仍存在于记忆工件中 |
| 未知 `type` 拒写 | 不知道它该落到哪个作用域、谁能读 | — |
| 空正文拒写 | 纯噪声 | — |
| `positioning` 只有协调会话能写 | L1 每轮全文注入、定义行为边界 | 权限矩阵 |
| **`tool-output`/`inferred` 不能单独取得工作区级效力** | 强制降级为 `review: pending`；带 `confirmed` 才放行 | `arXiv:2608.01679` 权限坍缩 |

第 5 条是这轮的语义核心：**内容可以记，效力不能自封**。工具输出与推断可以进库，但只能以"待审"身份进库——注入时降权并打上 `[pending]`。

## 3. 反回声：来源族

```js
familyOf({ sessionId, source, tool }) -> "fam_<10hex>"
```

同一会话、同一诱发来源写出的所有记录共享一个族。注入端 `dedupeByFamily` **每族只保留一条代表**，并在覆盖率里如实报告：

```
### L4 会话期记忆（2 条，按来源族去重 1 条，未审查项已标注）
```

测试覆盖了"同一证据被写两次 → 只占一个召回位置"。这是 `arXiv:2610.17763`（Memory Echo）的直接对策：**被重复阅读的历史不能伪装成独立佐证**。

## 4. 权限矩阵（实测行为）

| 操作 | worker | coordinator |
|---|---|---|
| 写自己的笔记 | ✔ | ✔ |
| **覆盖他人笔记** | ✘（提示改用 `memory_revise`） | ✔ |
| **修订他人正文** | ✘ | ✔（记录 `originalTextSha`） |
| **审查 approve/reject** | ✘ | ✔（记录 `by` + 时间 + 备注） |
| 失效化自己的笔记 | ✔ | ✔ |
| **硬删除** | ✘ | ✔ |

`memory_revise` 会记下被替换正文的 sha1，所以"原来写的是什么"永远可证。

`memory_forget` 的硬删除返回里明确写 **"git 历史里仍可找回"**——不假装删除等于消失。
