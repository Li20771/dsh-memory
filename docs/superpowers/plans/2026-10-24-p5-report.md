## 2. 一处对逆向建议的刻意偏离

逆向报告 §7.2 建议：**区间存 canonical 坐标，渲染时用 `toOriginal` 映回原文**。

我没有那么做，改为**直接存原文坐标**。理由：

- canonical 方案要求每篇笔记常驻一张 `canonical[i] → original[i]` 映射表。10k 篇 × 2KB ≈ **80MB** 常驻内存，只为了换算偏移。
- 原文坐标**直接可渲染**（切片就是高亮）、**直接可比较**，零额外内存。
- canonical 层仍然保留，用在它真正有价值的地方：**passage 切分（~900 字、零重叠）**。

代价是区间不能和 NotebookLM 的坐标直接对照——但我们本来也不打算跨系统比对。这个偏离记在这里，避免以后有人以为是漏了。

## 3. 四种引用状态，而不是"坏了"

`resolveCitation` 返回四种，因为"broken"会把三件不同的事混成一件：

| 状态 | 含义 | 为什么必须分开 |
|---|---|---|
| `ok` | 笔记在、revision 一致、块还在 | — |
| **`stale`** | 笔记在，但**内容变过** | 区间可能已指向别的字；必须重新确认，不能沿用 |
| `missing` | 笔记没了 | — |
| `moved` | 笔记没变，但**被引用的块 id 不在了** | 块被删/改写，锚点失效但文件仍在 |

`stale` 仍会返回**当前**文本，让人能对照"原来指什么、现在是什么"。

## 4. 句子级定位：逆向抄不到的那一层

NotebookLM 的引用精度上限是 passage——实测单事实查询返回整篇 `[0,612]`，跨章查询返回 888/916 字的单 passage。所以"点引用高亮到确切句子"它做不到，也没有参考实现。

我们的做法：`locateSentence(body, passage, claim)` 在 passage 内切句，按与 claim 的词元重叠打分选出最支持的那一句，返回**原文区间**。用的是与检索同一套可解释打分（无 embedding）。

`memory_search` 的输出因此变成三层：

```
1. projects/p1/findings.md#^blk1  (score 1.0)
   接口在并发 8 时丢事件，这是关键结论。
   rev=9c31abcdef12 句=42-63
```

- `#^blk1` = 可点回 Obsidian 的锚
- `rev=…` = 引用时看到的版本
- `句=42-63` = 句子级区间（passage 级的下一层）

## 5. 闭环：引用被持久化 + 自动审计

光能产生引用不够——不存下来，`verify` 就只是一次性的。

- `memory_write` 新增 `sources`（`path#^blk` 或 `path#Heading`），写入时**自动钉住目标当前 revision**（也可显式传 `ref@revision`）。
- 存储形如 `sources: ["projects/p1/findings.md#^blk1@9c31abcdef12"]`——纯字符串、可手改、当前 YAML 子集能读写。
- `memory_diagnose` 每次扫描所有带 `sources` 的笔记，重新解析 → 报 `引用审计: N 条｜陈旧 X｜失效 Y`。

测试验了完整链路：写入带引用 → 审计显示"陈旧 0" → 改目标笔记 → 审计变"陈旧 1"。

## 6. 一个会造成数据丢失的 bug（写测试时发现）

原映射：`finding` / `decision` / `question` 全部落到 `projects/<该笔记自己的 slug>/README.md`。

后果：**每写一条 finding 就会把"项目 README"覆盖成那条 finding**，而且不同 finding 之间互相覆盖。这是静默数据丢失，不是报错。

修法：引入 `project` 参数与目录映射——`projects/<project>/findings|decisions|questions|research|log|artifacts/<slug>.md`，只有 `type: project` 才写 `projects/<slug>/README.md`。已加测试锁定"写 finding 不会污染项目 README"。

## 7. 断链告警

`linkHealth(index)` 分离两类腐烂：

- **unresolved**：`[[nope]]` 指向不存在的笔记
- **ambiguous**：`[[dup]]` 同时匹配多个同名文件

`memory_diagnose` 输出 `链接健康: 1/3 解析成功｜断链 1｜歧义 1` 并列出前几条。

## 8. 局限：逐条判定与已采取的动作

初版列了 4 条局限。逐条追问"能不能解决"之后，实际状态是：**2 条彻底解决、1 条显著改善但有硬顶、1 条部分解决**。

| 局限 | 判定 | 已做 |
|---|---|---|
| 句子定位是词元重叠，非语义蕴含 | 🟡 **显著改善，消不掉** | **锚点优先匹配** + 返回 top-3 候选 |
| 没有 UI 高亮 | 🟡 **部分解决** | **行号区间**（`path:12-15`）→ 可跳转，不可高亮 |
| `stale` 不说"变了什么" | ✅ **彻底解决** | 存**引文快照**，审计报「引用时:「…」」 |
| 审计 O(N) 全库 | ✅ **彻底解决** | 按 index version 缓存，重复调用零成本 |

### 8.1 锚点优先：不引入 embedding 的解法

技术断言的支撑证据几乎总是**逐字复制**在原文里：数字与单位（`0.86 MPa`）、标识符（`ZX-9`、`dsh-memory`）、路径（`lib/index.js`）、引号内文本。`extractAnchors` 把这四类抽出来，句子打分时**锚点权重是普通词元的 3 倍**。

关键在于**失败方向是安全的**：如果连数字都不在句子里，那句大概率就不是支撑句。这比"词重叠"锐利得多，而且完全可解释、零依赖。

实测（新增测试）：claim 是「压力到 0.86 MPa 会怎样」，支撑句是「并发阈值设为 0.86 MPa 时开始丢事件」——**文字几乎不重叠**，靠锚点命中选对。

同时返回 **top-3 候选句**而不是只给一个猜测，让读者在拿不准时自己判断。

**仍然的硬顶**：纯概念断言（无数字、无标识符、纯同义改写）依然会漏。这是 D5（不做 embedding）的代价，我不打算偷偷塞一个向量库来假装消除它。

### 8.2 行号：不写 UI 也能跳转

`lineRangeOf(body, range)` 把字符区间换成 1-based 行号。检索输出因此带 `lines` 与 `sentenceLines`，形式是 `path:12-15`——**任何编辑器、终端、`git diff` 都能直接用**。

真正的"点击高亮"仍需要 client bundle + 一个文档查看器（P2 已查证 `dsh-client-ui-slots` 是浏览器侧平台模块，node 侧不可检查），那是另一个产品面，不是这一期能顺手做的。

### 8.3 本轮抓到的 bug

锚点在抽取时**剥掉了空格**（`0.86 MPa` → `0.86mpa`），但匹配时干草堆没剥，导致**带单位的数字永远匹配不上**——而带单位的数字恰恰是最重要的锚点。测试直接暴露了它。
