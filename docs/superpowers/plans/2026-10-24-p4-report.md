## 2. 收割契约：拒绝"我以为收完了"

```
active ──harvesting──▶ closing ──(7 天冷静期)──▶ purged
```

三条硬规则：

1. **每一条记录必须有处置**：`harvested`（带 target）/ `discarded`（带 reason）/ `deferred`。缺一条 → `finish` **拒绝**进入 `closing`，并把缺的路径列出来。
2. **收割中途新增的记录也会被算进去**。测试专门验了这个：处置完 A 之后又写了 C，`finish` 会拒绝并指出 C——这正是"我以为收完了"的真实形态。
3. **状态迁移是白名单**。`purged → active` 之类直接抛错；`harvesting → active` 是唯一允许的回退（收割卡住时宁可重开，而不是永久冻结一个段）。

状态写在**工作区 marker**（随仓库走），收割报告写在 vault 的 `workspaces/<id>/harvest/<ep>.md`（人可读可编辑）。处置行是刻意设计的纯文本格式：

```
- workspaces/ws_x/memory/a.md | harvested | target=workflows/y.md | at=2026-10-24T00:00:00Z
```

## 3. 销毁：可捞回 + 留墓碑，且不假装干净

`memory_purge` 分两步：

- **第一次调用只报告**：会被销毁多少条、收割覆盖多少、哪些**没收割就要被销毁**。不做任何删除。
- **`confirm=true` 才执行**：文件 `rename` 进 `.trash/<episode>/<时间戳>/`（保留 7 天），并向 `.trash/tombstones.jsonl` 追加一行墓碑（含 `moved`、`unharvested` 计数）。

返回里明确写两句不好听但必须说的话：

> 有 N 条未收割就销毁了——内容仍在 `.trash`，7 天内可捞回。
> 残余（不假装能清）：git 历史里仍可找回旧版本；已注入过的会话上下文里也仍有它。

墓碑的意义：**"这个项目存在过"本身是信息**，但内容必须消失。

## 4. supersedes：保留历史，不覆盖

`memory_write` 新增 `supersedes`：
- 旧记录标为 `status: superseded` + `supersededBy`，**正文原样保留**
- 新记录带 `supersedes` 指向旧记录
- 两条记录都存在于磁盘上，形成可追溯的版本链

**本轮抓到的一个真 bug**：如果新记录与它要取代的记录落**同一路径**（同名 slug），会把自己覆盖掉——本该保留的旧版本直接消失。修法是自动加版本号（`阈值.md` → `阈值-v2.md`），让两条都在。

**冲突标记**：两个记录都声称取代同一个前任时，第二条带 `conflict: 已被 X 取代`，由协调会话裁决，不静默取一个。

## 5. 停滞检测

`lastActivity` 写在 marker 里，每次 `memory_write` 更新。`memory_diagnose` 现在会报：

```
段状态: active（冷静期至 …，已到期）
最近活动: 2026-09-09T…  ⚠ 已停滞 45 天（阈值 30）：该收割或放弃
收割覆盖: 0/1（未处置 1 条）
```

这条是给"暂时性"兜底的：项目停半年不会悄悄变成事实上的长期记忆。

## 6. 一个要盯的趋势：工具数

4 → 7 → **9 个**。每个工具的 schema 都是**每次请求的固定 token 成本**。现在总量还不大，但这条线该刹了。

建议在 P6 之前做一次合并：把 `memory_harvest` 的 `action` 模式推广——`memory_write`/`memory_revise`/`memory_review`/`memory_forget` 其实可以合成一个 `memory_edit(action)`，`memory_purge` 并入 `memory_harvest(action=purge)`。预计能从 9 降到 **5**，schema 成本减半，且不损失能力。

这条我记进了待办，但**没有擅自做**——合并会改变工具名，属于对外契约变更，等你点头。
