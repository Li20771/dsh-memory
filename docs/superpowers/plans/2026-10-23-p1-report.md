## 2. 三个设计决定（值得记住的）

### 2.1 代码掩码而不是删除
链接和标签扫描跑在**等长的掩码文本**上（围栏代码块与行内代码替换成等量空格）。这样 `[[x]]` 写在代码里是惰性的，而**所有偏移量仍然指向原文**——引用能精确高亮，靠的就是这一点。

### 2.2 身份是仓库相对路径，永不绝对路径
`fileId = "projects/p1/README.md"`。这是可迁移性的地基：仓库搬到别的盘、别的机器，没有任何存储数据引用"它在哪"。

### 2.3 两段式变更检测
先 `stat`（mtime + size），只有变了才读文件比内容哈希。原因很实际：**`git checkout` 会刷新所有 mtime 但一个字节都没变**，为此重解析 10k 篇是纯浪费。测试里覆盖了这条（同字节不同 mtime → 复用旧解析）。

## 4. 性能：实测，且未达计划目标

**实测（`node tools/vault-bench.mjs 2000`）**：

| 指标 | 2000 文件 | 线性外推 10k |
|---|---|---|
| 全量重建 | **798ms**（399µs/文件） | ≈ 4.0s |
| 空转刷新（无变化） | **70ms** | ≈ 350ms |
| 单文件变更刷新 | **60ms** | ≈ 60–300ms |

**计划里我写的是「10k 全量重建 <2s，增量 <50ms」，实际是 ~4s / ~350ms。目标未达成，如实上报。**

判断与修法：

- **全量重建 ≈4s 可接受**——它只在进程启动时发生一次，且可以做后台化，不进请求路径。
- **空转刷新 ≈350ms 不可接受**——它挂在每个 pre-step 上，会拖慢每一轮。根因是每次都要 `readdir` 全树 + `stat` 每个文件。

**修法（P2 落地，且正好复用 DSH 自己的设计）**：改成 **touch 驱动**。
`dsh-agent-instructions` 的做法值得照抄：不去猜文件变没变，而是监听 `tools/result`，只对**本次真正被 read/write/edit 触碰过的路径**做刷新；再叠一个低频（如 30s）的全量 stat 作为兜底。

这样常态下每轮只 stat 0–3 个文件，成本降到 **<1ms**。

我在计划里把这条标为 P2 的必做项，而不是"优化项"——因为不修它，10k 规模下每轮多 350ms 是实打实的体验退化。

## 5. 给逆向结果的落点（重要）

你的 P0 ③④ 结果到了之后，**只需要改 `plugin/lib/vault/links.js` 这一个文件**。它对外只暴露四个契约：

```js
extractLinks(masked, baseOffset) -> LinkHit[]
  LinkHit = { embed, raw, target, anchor, block, alias, start, end }

resolveTarget(normalizedTarget, lookup) -> Resolution
  Resolution = { kind:'self'|'file'|'ambiguous'|'unresolved', fileId?, candidates? }

resolveAnchor(parsed, anchor, block) -> { kind:'block'|'heading'|'none', start, end }

normalizeTarget(target) -> { path, base }   // 小写、posix、去 .md
```

`index.js` 和 `query.js` 只消费这些返回值，不碰文法本身。所以：

- 若 Obsidian 的 `[[N#^blk]]` 解析规则与我不同 → 改 `resolveAnchor`
- 若同名消歧规则不同 → 改 `resolveTarget`
- 若还有我没支持的写法 → 改 `extractLinks`
- **测试套件会立刻告诉你哪条语义变了**

## 6. 当前已知的语义假设（等你的逆向结果校准）

| # | 假设 | 若实际不同会怎样 |
|---|---|---|
| 1 | `[[N\|alias]]` 的 alias 仅影响显示 | 若它也参与消歧，改 `extractLinks` |
| 2 | 同名文件消歧：精确路径 > 唯一 basename > ambiguous | 改 `resolveTarget` |
| 3 | 大小写不敏感匹配文件 | 改 `normalizeTarget` |
| 4 | 块 = 段落，或（若该行是列表项）该列表项 | 改 `parse.js` 的块扩张逻辑 |
| 5 | `^id` 必须显式书写，**不自动生成** | 若 Obsidian 会按设置自动生成，需加生成策略 |
| 6 | 标题区间 = 到下一个同级或更高级标题 | 与 Obsidian 一致的概率较高，但仍待确认 |
| 7 | 前言行首必须是无缩进的 `---` | Obsidian 同此，风险低 |
