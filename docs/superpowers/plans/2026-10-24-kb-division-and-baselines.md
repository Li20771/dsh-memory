## 一、两个数字到底怎么测的

### 0.713 vs 0.775（arXiv:2609.29144）

**不是两套系统对比，是干预式配对对照。**

- 指标是 **MTU** = 13 个 checkpoint（T=12，t=0..12）上 hidden utility 的均值，**不是终局分**。
- 同 8 条 paired stream、**同 proposals、同门决策、同任务程序、同分数**，只改一个变量：**task→skill 的指配作用域**。
  - Global：一份 360 字全局 skill 覆盖所有族
  - Scoped：接受的候选只进本族 slot，其他族回落到 K₀
- 两种做法 **prompt 预算完全相同**（skill 文本统一 pad 到 360 字符）。
- 结果：Static 0.775、Global-ORC **0.713**（−0.062，即"有记忆比没记忆差"）、Scoped-ORC **0.816**；有害接受 Global **6/8**、Scoped **0**。
- 族级证据：那条规则抬高 boundary，同时把另外四族各自压低 **−0.461 / −0.234 / −0.148 / −0.117**。
- 模型：Qwen3-Coder-Next，temp 0，actor 700 tok / editor 500 tok，provider fallback 关闭。
- **扩展**：27 条配对流上 Scoped−Global **+0.063 [0.037, 0.094]**，接受 63 vs 12，**有害接受 0/63**。

**限定**：9 个 code-contract 族语义固定，seed 只变 token/名字/程序变体，**不变语义**。所以它测的是"程序化实例化的熟悉契约"，不是"适应随机新语义"。

### 82% 上下文暴露（arXiv:2609.36373）

- 单位 = **一次物理模型调用实际组装出的确切上下文**（不是检索结果列表，不是最终回复）。
- 每个 context 有 viewer 集合 `V(C)`（该轮在场的传输层身份）；**解析不出 viewer 就 fail-closed 到 public-only**。
- 准入判据：某项进入 context **当且仅当 `V(C)` 里每一个 viewer 都在它的 authorized audience 里**；任一不在 → 不得进入。**用排除实现，不依赖模型行为**。
- forbidden 判据：该项**在 context 里**，且授权 audience **不含某个当前 viewer**。
- **计数单位是 context，不是 item**：一个 context 里 ≥1 个 forbidden 就算"暴露"。
- 分母：unscoped 臂 **100,000** 个 context，其中 **82,266** 个含 forbidden → **82%**。对照臂（B-Flat/B-Graph 各 200,000，silo/post-filter/principal 各 180,000）**一个都没有**。
- 设置：10,000 条合成历史（8 主题 × 1,250），**ledger 在语言渲染之前就固定**；6 臂共用同一查询/状态/模型/prompt/**确定性词法索引**（FTS5 BM25 + RRF，fetch 20、k=5）；**确认性排序不用 embedding**；剂量 d ∈ {0,1,2,4,8}。
- **配套召回代价**：unscoped R@5 **0.674** → 作用域化臂 **0.972**（配对 Δ +0.298）；temporal-update 单题上 unscoped 从 0.974(d=0) 掉到 0.616(d=8)，两个架构在所有剂量稳定 0.974。**即：作用域化不是拿召回换安全，它同时提升了召回**（forbidden 项不再抢 slot）。
- 作者原话：**"Inference concerns this generator, not natural prevalence."**

## 二、这两个数字在本系统里的用途

| 用途 | 说明 |
|---|---|
| **① 只借定义，不借数字** | 0.775 依赖特定任务族结构与 prior competence；82% 依赖 8 主题 × d=8 重剂量。照抄会得到假结论。**能搬的是对比条件与指标定义。** |
| **② 已做成 CI** | `tools/exposure.test.mjs` 把 36373 的暴露率定义实现成测试：单位=一次组装出的记忆块，观众=当前工作区，per-context 计数，**必报分母 N**。当前 `exposure_rate = 0/3`。 |
| **③ 可证伪** | 同文件 §2 是对照组：那条外部记录**确实在库里、确实能被检索到**，只是进不了上下文。没有这一步，"0 暴露"可能只是"记录是坏的"。 |
| **④ 一条反直觉的收获** | 36373 的召回表说明：**作用域化同时提升召回**（0.674→0.972）。所以我们按工作区隔离 L4 **不是在牺牲召回**，反过来是对的。 |

**不能说的话**（记住这几条，避免以后误用）：
- 不能说"我们的暴露率低于 82%，所以我们更安全"——必须在**自己的语料**上跑未防护臂，得自己的数字。
- 不能说"0.713 是记忆的普遍代价"——那是 8 条流恰好都接受同一条 boundary 规则的结果。
- 两篇的 "context" 含义不同（一次模型调用 vs 360 字 skill 文本），混用会把"泄漏"和"干扰"搅在一起。

## 三、知识库写入分工（最佳方案）

### 原则：按「谁能作出这个断言」分，不按级别分

用级别分会产生两类错误：协调会话写它没测过的**发现**（升格风险），执行会话写它无权裁决的**决策**（越权）。

| KB 位置 | 内容 | 谁写 | 何时 |
|---|---|---|---|
| `projects/<slug>/README.md` | 背景 / 目标 / **非目标** / 入口 | 协调会话 | 开工前 |
| `research/` | 调研、方案选项、外部证据 | 协调会话 | 开工前 / 遇岔路 |
| `decisions/` | ADR：选项 + 理由 + **什么情况下重议** | 协调会话裁决（执行会话可写 `proposed`） | 决策当时 |
| `findings/` | 实测结论（带 authority） | **执行会话** | 测得当时 |
| `questions/` | 未解问题 + 什么证据能回答 | 两边都写 | 随时 |
| `log/` | 执行流水 | 执行会话 | 随时 |
| `artifacts/` | 产物索引 | 执行会话 | 产出时 |

### 交叉规则

- 执行会话可以写 `decisions/`，但只能 `status: proposed`；只有协调会话能改成 `accepted`。
- 协调会话可以修订执行会话的 `findings`，但必须走 `memory_revise`（保留 `originalTextSha`）。

### 时机分工 —— 这条解决"收割时失真"的根本问题

```
开工前   协调会话：README + research + decisions(计划)
执行中   执行会话：log + findings + questions   ← 结论出现即写，不等收尾
收尾     协调会话：只做复核（verify），不做回忆（recall）
```

**收割的性质因此改变**：从"从记忆里回忆出成果"退化成"逐条确认 KB 里已有条目仍在、仍准"。语义风险被降级成机械检查。

### L4 与知识库：职责不同，不是内容切割

**L4 的职责始终是「工作区强化记忆」**：让同一工作区的多次会话能接力，不用重复交代背景、不重复踩同一个坑。因此它承载的是**这个项目当前需要知道的一切**——结论、决定、卡点、试过什么、为什么放弃。**分工不改变这一点。**

知识库是**长期沉淀**：跨项目、跨时间可查、可复用。结论写进知识库**不排挤 L4**——L4 里仍要留结论，否则下个会话还得先去翻知识库，那就失去"强化"的意义了。

两者的差别只在**取材**：

| | L4（工作区强化） | 知识库（长期沉淀） |
|---|---|---|
| 覆盖 | 本项目当前所需的全部上下文 | 值得长期留存与复用的结论 |
| 寿命 | 收割后销毁 | 永久 |
| 谁写 | 会话过程中自动/主动记 | 按 §三 的分工取材：协调写意图与裁决，执行写观察与结果 |

`supersedes` / `sources` 这类反向链接是**可选的额外收益**（收割时靠它确认结论已在别处、且没被改），不是"L4 只许存过程"的理由。

## 四、三个写入门禁（代码强制，不是提示词建议）

| 门禁 | 触发 | 理由 |
|---|---|---|
| `decision-needs-alternatives` | `type: decision` 且 `alternatives` < 2 | 「选 A 不选 B 的理由」的前提是 B 真的存在；只记一个的"决策"是事后叙事 |
| `project-needs-nongoals` | `type: project` 且 `nonGoals` 为空 | 没有非目标的"范围"等于没有范围，后面什么都能塞进来 |
| `harvested` 目标必须存在 | `memory_harvest` 记 `harvested` 且 target 不在库里 | 否则"收割完成"可以是一句空话，而这个空话会授权销毁 |
| （警告）收割目标未回引来源 | target 的 `sources` 不含该记录 | 来源链断了，事后查不到出处。不阻止通过，但明确告警 |

## 五、残余风险（改不了的部分）

1. **收割者没有当时的推理链**：缓解是"执行中即写"，但泄漏到 L4 之外的东西仍然只能靠记录者的自律。
2. **`authority` 依赖写入者不升格**：门禁能强制"决策有选项"，不能强制"这个选项描述是真的"。
3. **暴露率只覆盖工作区维度**：条目级的更细 audience（如"这条只给某个角色看"）尚未建模，当前粒度是 scope。
4. **82% 与我们无关**：我们的数字必须自己测。当前是 `0/3`，样本量小，只能说明"机制成立"，不能说明"语料越大仍为 0"。要提升可信度需扩大 fixture。
